# 视觉资产包（.vpk）设计稿

> 状态：已定稿，已在 PF.Vision.Halcon 1.1.0 / PF.Modules.Halcon 1.1.0 实现（以代码为准）。适用：`PF.Vision.Halcon`（格式、会话、读取）+ `PF.Modules.Halcon`（编辑器界面）。
> 本版是新格式的第一版，取代旧 `.roipk`，**不兼容旧包**（旧包需要重新建）。
>
> 第三稿变更：图像条目改为"原图"，默认无损 PNG，可选按原文件原样存储或其它格式；取消草稿——
> 编辑会话只在内存中，保存即生效，不保存就丢弃；布局版本要求完全相等；保存时记录当前登录用户。
>
> 范围外（后续单独讨论）：视觉配方上传服务器、使用时下载的流程；各消费项目（如 MappingShift）的迁移。
> 本稿只定格式、本地编辑与本地读取。

---

## 1. 背景与目标

现在的 `.roipk` 是固定三件套：`model.shm` + `rois.json` + `reference.jpg`（外加可选 `meta.json`），
由 `ShapeTemplateService.SaveTemplate` 一次写死。实际使用中暴露出三个问题：

| 问题 | 现状数据（MappingShift） |
|---|---|
| 多个模板基于同一张图时，图重复存储 | 匹配点 / 校验点两个包各存一份同一张图（各 10 MB），配方包 8~20 MB |
| 内容固定，项目没法按需组合 | MappingShift 新方案只要"图 + 两个 ROI + 行列号"，不要 `.shm`，现格式装不下也去不掉 |
| 没有依赖关系 | 图或 ROI 改了，不知道 `.shm` 是不是过期；也无法判断导入的图是不是 ROI 当初画的那张 |

**目标**：

1. 包的内容由一份**清单（manifest）**描述，项目通过**布局（目录配置）**声明自己的包里有哪些条目。
2. 条目之间的**依赖**显式记录：知道 ROI 画在哪张图上、`.shm` 由哪张图 + 哪个 ROI 生成；
   图或 ROI 改了，能判断哪些派生内容过期并重新生成。
3. 原图在一个包里只存一份，默认无损，保证随时能打开包重新编辑、重新生成。
4. 生产端按名字取有类型的内容，只解压需要的条目，不为原图付开销；打开时校验布局版本。
5. 编辑器统一：左侧按布局显示树，点叶子节点在右侧打开对应编辑页，最后校验并保存。

**不做**：旧包兼容；草稿；包内容加密；多人协同编辑；包内历史版本。

## 2. 概念

| 名词 | 含义 |
|---|---|
| **包（Package）** | 一个 `.vpk` 文件（zip），里面是 `manifest.json` + 各条目的数据文件 |
| **条目（Entry）** | 包里的一项内容，有唯一 `id`、`kind`（类型）、数据文件、依赖。例如一张原图、一组 ROI、一个形状模型 |
| **条目类型（Kind）** | 决定条目怎么存、怎么校验、怎么生成、用哪个编辑页。框架内置几种，项目可扩展（§8） |
| **源条目 / 派生条目** | 源条目由人输入（导入图、画 ROI、填参数）；派生条目由程序根据依赖**生成**（形状模型），不能手工编辑 |
| **布局（Layout）** | 项目声明的"目录配置"：这类包里应该有哪些条目、各是什么类型、谁依赖谁、树怎么分组、哪些必填；带**布局版本** |
| **修订号（Revision）** | 包内容的版本，每保存一次加 1 |
| **编辑会话（Session）** | 打开或新建一个包后的可编辑状态，只在内存（+ 临时目录）里；`Save` 才写回 `.vpk`，不保存关闭即丢弃 |
| **读取器（Reader）** | 生产端只读访问包的入口，不解析编辑相关内容 |

## 3. 包格式

### 3.1 目录结构

```
xxx.vpk  (zip)
├─ manifest.json              ← 必有，描述包与全部条目
├─ images/<entryId>.<扩展名>  ← 原图（默认 .png 无损；或原文件原样，扩展名沿用原文件）
├─ rois/<entryId>.json        ← VisionRoiConfig 列表（原图坐标）
├─ models/<entryId>.shm       ← 形状模型（派生）
├─ data/<entryId>.json        ← 参数类条目（Data<T> 序列化）
└─ files/<entryId>/<原文件名>   ← 附件类条目（原样保存，比如参考 mapping 文件）
```

- 条目数据的存放路径由 `kind` 决定，manifest 里也记录了实际路径，读取时**一律以 manifest 为准**，不靠约定路径猜。
- 文件名一律用 `entryId`，不用中文显示名，避免 zip 里中文编码问题。
- 已经是压缩格式的文件（PNG、JPEG、压缩 TIFF）在 zip 里不再压缩（`NoCompression`），省保存时间。

### 3.2 manifest.json

```jsonc
{
  "format": "PF.VisionPackage",
  "formatVersion": 1,                       // 框架包格式版本（§7.2 校验）
  "layout":   { "id": "Sample.GridPoints", "version": 1 },   // 布局及版本（§7.2 校验，要求完全相等）
  "revision": 3,                            // 内容修订号，每次保存 +1
  "savedAt": "2026-10-10T10:20:00+08:00",
  "savedBy": "工程师A",                     // 保存时的当前登录用户
  "entries": [
    {
      "id": "Image",
      "kind": "Image",
      "title": "原图",
      "path": "images/Image.png",
      "contentHash": "sha256:…",          // 本条目存储文件的哈希（防损坏，也是给下游的指纹）
      "attrs": {
        "sourceName": "LineScan_081349.tiff",
        "sourceHash": "sha256:…",          // 导入时原始文件的哈希，用于"是不是同一个文件"的提示
        "width": 11000, "height": 16384, "channels": 1, "pixelType": "byte",
        "storage": "Png"                   // Png | Original | Tiff | Bmp | Jpeg（见 §4.1）
      }
    },
    {
      "id": "MatchPoint.Roi",
      "kind": "Roi",
      "title": "匹配点 ROI",
      "path": "rois/MatchPoint.Roi.json",
      "contentHash": "sha256:…",
      "dependsOn": { "image": "Image" },
      "inputs":    { "image": "sha256:…" },   // 画 ROI 时那张图的指纹（见 §5）
      "attrs": { "bbox": [9590, 3334, 9780, 3550] }
    },
    {
      "id": "Model",
      "kind": "ShapeModel",
      "title": "形状模型",
      "path": "models/Model.shm",
      "contentHash": "sha256:…",
      "dependsOn": { "image": "Image", "roi": "MatchPoint.Roi" },
      "inputs":    { "image": "sha256:…", "roi": "sha256:…", "options": "sha256:…" },
      "attrs": { "options": { "angleStart": -0.39, "angleExtent": 0.79, "metric": "use_polarity", "minContrast": 10 } }
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `formatVersion` | 框架包格式版本，本版为 1。读取器只认自己支持的版本 |
| `layout.id / version` | 这个包按哪个布局、哪个布局版本建的。程序打开时校验，**必须完全相等**（§7.2） |
| `revision` | 内容修订号。新建的包首次保存为 1，之后每次保存加 1 |
| `savedAt / savedBy` | 最后一次保存的时间与用户（调用方传入当前登录用户） |
| `entries[].id` | 包内唯一，只允许字母、数字、`.`、`_`、`-`，用作文件名和 API 取值的键 |
| `contentHash` | 条目数据文件的 SHA-256 |
| `dependsOn` | `角色 → 条目 id`。角色名由 kind 定义（如 ShapeModel 需要 `image`、`roi` 两个角色） |
| `inputs` | 生成/绘制时各依赖的**指纹**快照，用来判断是否过期（§5） |
| `attrs` | kind 自己的属性，结构由 kind 定义 |

> 两个版本号放在 manifest 固定字段而不是做成条目：打开包第一件事就是读 manifest，在这里校验最直接；
> 版本号也不需要条目的状态 / 依赖机制。
>
> 因为没有草稿，磁盘上的 `.vpk` 一定是完整、各条目一致的（保存前强制校验，§7.3），manifest 里不需要记录条目状态。

## 4. 内置条目类型（首批）

| Kind | 类别 | 依赖角色 | 存储 | 给下游的指纹 | 编辑页 |
|---|---|---|---|---|---|
| `Image` | 源 | — | `images/<id>.<扩展名>` | 存储文件哈希 | 导入、预览、显示尺寸/来源/存储方式 |
| `Roi` | 源 | `image: Image` | `rois/<id>.json`（`VisionRoiConfig` 列表） | 文件哈希 | 在依赖的图上画/改 ROI（复用现有 ROI 绘制控件） |
| `ShapeModel` | 派生 | `image: Image`, `roi: Roi` | `models/<id>.shm` | 文件哈希 | 建模参数、生成、在原图上试找并叠加轮廓 |
| `Data<T>` | 源 | — | `data/<id>.json` | 文件哈希 | 按 `T` 用 PropertyGrid 编辑 |
| `File` | 源 | — | `files/<id>/原文件名` | 文件哈希 | 导入、导出、显示文件信息 |

### 4.1 原图

存储方式由布局按条目声明（`storage`），默认 `Png`：

| storage | 含义 | 是否无损 | 说明 |
|---|---|---|---|
| `Png`（默认） | 导入后转成 PNG（HALCON `png fastest`） | 是 | 所有工具都能打开。11000×16384 灰度图实测写 3.0 s、77 MB（默认压缩级别要 22.6 s、65 MB，不划算） |
| `Original` | **原文件字节原样存**，扩展名沿用原文件 | 取决于原文件 | 需要保留相机原始文件（比如带元数据的 TIFF）时用 |
| `Tiff` | 转成压缩 TIFF | 是 | 需要 TIFF 格式交付时用 |
| `Bmp` | 转成 BMP | 是 | 不压缩，体积最大，一般不用 |
| `Jpeg` | 转成 JPEG（质量可配，默认 90） | **否** | 仅在体积优先、且不需要精确重新生成时用 |

- **生成一律用存储版**：导入原图时按 `storage` 生成存储版文件，会话里后续所有操作（显示、画 ROI、
  **生成形状模型**）都解码存储版，不用导入时的原始文件。无损方式下两者像素完全一样；
  有损方式（Jpeg）下这条规则保证第一次生成和以后重新生成的输入是同一份像素，结果可重复。
- 图像的指纹 = 存储文件的哈希。`sourceHash`（导入时原始文件哈希）只用于导入时提示"这和当前图是不是同一个文件"。

实测（11000×16384 灰度，新建 + 导入 + 保存）：

| storage | 图像文件 | 包大小 | 耗时 |
|---|---|---|---|
| `Png` | 77 MB | 77 MB | 约 3.5 s |
| `Original`（TIFF 未压缩） | 172 MB | 78 MB（zip 再压缩） | 约 2.7 s |
| `Tiff` | 78 MB | 78 MB | 约 4.5 s |
| `Jpeg`（90） | 13 MB | 13 MB | 约 1.2 s |

### 4.1.1 形状模型的指纹

`.shm` 文件头带生成时间：同一份输入重新生成，模型等价（实测匹配结果完全相同），但文件字节不同，指纹也不同。
因此"模型的指纹变了"不代表模型内容变了；目前没有条目依赖形状模型，不影响状态判断。

### 4.2 `Data<T>`

- 布局声明 `Data<T>("id", …)`，读取时 `GetData<T>("id")`，`T` 是普通的 C# 类（`System.Text.Json` 序列化）。
- **宽松反序列化**：JSON 里缺的字段取 `T` 的默认值，多出的字段忽略，不报错。
- **约束**：字段改名、改含义时必须升布局版本（§6.3），否则旧值会悄悄变成默认值而没人发现。
- **可选自校验**：`T` 实现 `IVisionPackageData`（只有一个 `Validate()` 方法，返回错误列表）时，
  保存前和读取时都会调用——用来挡住宽松反序列化放进来的非法默认值（比如行列号为 0）。

```csharp
public sealed class GridCell : IVisionPackageData
{
    public int Row { get; set; }     // 1 起
    public int Col { get; set; }
    public IEnumerable<string> Validate()
    {
        if (Row < 1) yield return "行号须 ≥ 1";
        if (Col < 1) yield return "列号须 ≥ 1";
    }
}
```

## 5. 依赖与一致性

### 5.1 依赖图

- 条目 + `dependsOn` 构成一张有向无环图。打开/保存时校验：被引用的 id 存在；类型匹配角色要求
  （`ShapeModel.roi` 必须指向 `Roi`）；没有环。
- 生成、重新生成一律按**拓扑顺序**进行。

### 5.2 条目状态（只存在于编辑会话中）

| 状态 | 含义 | 树上显示 |
|---|---|---|
| `Missing` | 布局要求有，但还没建 | 灰色，"未建立" |
| `Ok` | 有数据，且 `inputs` 与各依赖当前的指纹一致 | 绿色 |
| `Stale` | 有数据，但某个依赖的指纹已经变了（依赖改过） | 橙色，"需重新生成"/"需确认" |
| `Invalid` | 有数据，但已经不能用（依赖缺失、尺寸对不上、生成失败、自校验不通过） | 红色，附原因 |
| `Extra` | 包里有，布局里没有（布局升级后遗留） | 斜体，可删除 |

判断规则：对每个条目，把 `inputs[角色]` 与 `dependsOn[角色]` 所指条目**当前的指纹**比较；
任一不同 → `Stale`；依赖本身是 `Missing`/`Invalid` → 本条目 `Invalid`。状态**向下游传播**。

### 5.3 典型变更场景

**A. 给图导入一张新图片（替换 `Image`）**

导入时先与当前图比对：

| 比对结果 | 处理 |
|---|---|
| 原始文件哈希相同 | 同一个文件，提示"与当前图相同"，不做任何改动 |
| 尺寸（宽、高、通道、像素类型）**不同** | 弹框确认："新图尺寸与原图不同，依赖它的 N 个 ROI 将失效"。确认后这些 ROI → `Invalid`（坐标可能越界，必须重画），其下游派生条目 → `Invalid` |
| 尺寸相同、内容不同 | 弹框确认："依赖它的 N 个 ROI 将保留坐标，请逐个确认位置"。ROI → `Stale`（需要人看一眼点"确认"），派生条目 → `Stale` |

"确认 ROI"操作：在新图上显示原 ROI，人工确认或微调后保存，ROI 的 `inputs.image` 更新为新图指纹，状态回到 `Ok`。

**B. 修改 ROI** → ROI 指纹变化 → 依赖它的 `ShapeModel` 变为 `Stale`。

**C. 修改建模参数** → `ShapeModel` 的 `inputs.options` 与当前参数不同 → `Stale`。

**D. 删除一个被依赖的条目** → 删除前提示下游受影响的条目；删除后下游 → `Invalid`。

### 5.4 重新生成与保存

- 编辑页上"生成/重新生成"只处理当前条目（及其必须先生成的上游）。
- 工具栏"全部重新生成"：按拓扑顺序处理所有 `Stale` 的**派生**条目。
- **`Stale` 的源条目（如 ROI）不能自动"重新生成"**，只能人工确认（场景 A）。
- **保存**：先自动重新生成所有 `Stale` 的派生条目；如果仍存在 `Missing`（必填）、`Invalid`、
  需要人工确认的 `Stale` 源条目或自校验错误，**拒绝保存**，界面列出原因。没有"存一半"的状态。
- **关闭**：有未保存的修改时提示"放弃修改？"，确认后丢弃，磁盘上的 `.vpk` 保持上一次保存的内容。

### 5.5 指纹计算

- 所有条目：存储文件内容的 SHA-256。
- 派生条目的 `inputs`：生成时把各依赖的指纹 + 生成参数（规范化 JSON 的哈希）逐个记下来。
- 只用哈希判断"变没变"，不比时间戳——文件被拷来拷去时间戳不可靠。

## 6. 布局（目录配置）

### 6.1 声明方式

由项目**在代码里声明**（有类型检查，写错编译就报错），启动时注册到框架。示例：

```csharp
// 通用"图 + ROI + 形状模型"布局（等价于现在的 .roipk 三件套）
var shapeTemplate = VisionPackageLayout.Create("PF.ShapeTemplate", version: 1)
    .Group("输入")
        .Image("Image", "原图", required: true)                       // 默认 storage: Png
        .Roi("Region", "模板区域", image: "Image", required: true)
    .Group("生成")
        .ShapeModel("Model", "形状模型", image: "Image", roi: "Region",
                    options: new ShapeTemplateCreateOptions())
    .Build();

// 示例：一张图上两组"ROI + 行列号" + 一个附件，不需要 .shm（模板由算法自己生成的场景）
var gridPoints = VisionPackageLayout.Create("Sample.GridPoints", version: 1)
    .Image("Image", "原图", required: true, storage: ImageStorage.Original)   // 原文件原样保存
    .Group("匹配点")
        .Roi("MatchPoint.Roi", "匹配点 ROI", image: "Image", required: true)
        .Data<GridCell>("MatchPoint.Cell", "匹配点行列号", required: true)
    .Group("校验点")
        .Roi("VerifyPoint.Roi", "校验点 ROI", image: "Image", required: true)
        .Data<GridCell>("VerifyPoint.Cell", "校验点行列号", required: true)
    .Group("附件")
        .File("ReferenceMapping", "参考 Mapping 文件", extensions: [".txt"])
    .Build();
```

- `Group` 只影响树的分组显示，不进 manifest（manifest 只记录条目）。
- 每个条目都可以声明：`required`、kind 专属参数（建模参数默认值、图像存储方式、文件扩展名限制）。

### 6.2 以后可选：JSON 布局

代码声明稳定后，可以再支持从 JSON 读布局（同样的结构），方便不改代码调整目录。首版不做。

### 6.3 布局版本什么时候升

| 改动 | 升版本？ |
|---|---|
| 新增一个可选条目 | 不必（旧包打开后该条目为 `Missing`，可选不影响保存） |
| 新增一个必填条目、删除条目、改条目 id / kind / 依赖、改图像存储方式 | **升** |
| `Data<T>` 的 `T` 新增字段（默认值可接受） | 不必 |
| `Data<T>` 的 `T` 字段改名、改含义、改单位 | **升** |

升版本后，旧版本布局建的包在编辑器里打开：布局新增的条目 → `Missing`，删掉的条目 → `Extra`，
处理完保存即按新版本写回（修订号 +1）。生产读取器遇到版本不等直接拒绝（§7.2），不会误用。

## 7. 程序接口

### 7.1 编辑会话（调试/建模用）

```csharp
// 新建 / 打开。会话只在内存（+ 临时目录）中，Save 之前磁盘上的 .vpk 不变
using VisionPackageSession s = VisionPackage.Create(layout);
using VisionPackageSession s = VisionPackage.Open(path, layout);

// 状态与结构
IReadOnlyList<PackageEntryState> s.Entries;                   // id、kind、分组、状态、原因、依赖
PackageEntryState s.GetState(id);
IReadOnlyList<PackageEntryState> s.GetDependents(id);         // 删除 / 换图前提示受影响的条目
int  s.Revision;                                              // 磁盘上最后一次保存的修订号（新建为 0）
int  s.LoadedLayoutVersion;                                   // 打开的包原来的布局版本
bool s.IsDirty;                                               // 有未保存的修改
event EventHandler s.Changed;                                 // 任何修改（含保存）后触发，编辑器据此刷新

// 源条目操作
ImportImageResult s.ImportImage("Image", imagePath);          // 原来没图或无下游时直接生效；否则 RequiresConfirmation
void s.ConfirmImageReplace(ImportImageResult r);              // 确认替换
void s.CancelImageImport(ImportImageResult r);                // 放弃替换
HObject? s.GetImage("Image");                                 // 存储版图像的拷贝（显示 / 画 ROI 用），所有权归调用方
void s.SetRois("MatchPoint.Roi", IReadOnlyList<VisionRoiConfig> rois);
void s.ConfirmRoi("MatchPoint.Roi");                          // 换图后人工确认 ROI 位置
void s.SetData<T>("MatchPoint.Cell", T value);                // 另有非泛型 SetData(id, object) / GetData(id) 供 PropertyGrid
T    s.GetData<T>("MatchPoint.Cell");                         // 没有数据时返回 new T()
void s.SetFile("ReferenceMapping", filePath);
string? s.GetFilePath("ReferenceMapping");                    // 会话临时目录里的附件路径（只读查看）
void s.Remove(id);

// 派生条目
void s.SetOptions("Model", ShapeTemplateCreateOptions options);
void s.Regenerate(id);                                        // 含必要的上游
void s.RegenerateAllStale();

// 校验与保存
PackageValidation s.Validate();                               // 列出 Missing / Invalid / 待确认 / 自校验错误
void s.Save(path, string savedBy);                            // 自动重新生成派生条目；不完整则抛出带原因的异常；修订号 +1
// 不调 Save 直接 Dispose = 放弃本次所有修改
```

- `savedBy` 由调用方传入当前登录用户（框架身份模块）。
- 保存时先写到同目录的临时文件，成功后再替换原文件，避免保存中途失败把原包写坏。
- 所有方法只在调用线程上同步执行，耗时的生成/保存操作由界面放到后台线程（与现有 `ShapeTemplateService` 的线程约定一致）。

### 7.2 读取器（生产用）

```csharp
// 打开时声明期望的布局：id 与版本都必须完全相等
using var pkg = VisionPackageReader.Open(path, expect: new LayoutRequirement("Sample.GridPoints", version: 1));

pkg.Revision;                                                 // 内容修订号，生产日志里记下来
pkg.SavedAt; pkg.SavedBy;
pkg.Has("Model");
ShapeTemplateHandle   h    = pkg.LoadShapeModel("Model");     // 只解压这一个 .shm
IReadOnlyList<VisionRoiConfig> rois = pkg.GetRois("MatchPoint.Roi");
GridCell              cell = pkg.GetData<GridCell>("MatchPoint.Cell");   // 宽松反序列化 + 自校验
string                file = pkg.ExtractFile("ReferenceMapping", destDir);
string                shm  = pkg.ExtractRaw("Model", destDir); // 需要裸文件时（比如把路径传给 HDevelop 过程）
```

打开时的校验（任一不通过即抛出带中文原因的异常）：

| 检查 | 失败提示示例 |
|---|---|
| `format` / `formatVersion` 是本框架支持的 | "视觉资产包格式版本 2 高于当前框架支持的 1，请升级框架" |
| `layout.id` 与期望相等 | "视觉资产包 [产品A] 的布局是 PF.ShapeTemplate，程序需要 Sample.GridPoints" |
| `layout.version` 与期望相等 | "视觉资产包 [产品A] 的布局版本是 1，程序需要 2，请在编辑器中打开并重新保存" |

读取条目时再校验：条目存在、`contentHash` 与文件一致（防损坏）、`Data<T>` 自校验通过。

- 读取器不提供任何解码原图的方法；需要图的场景（调试界面）走编辑会话。
- 读取器只认本地文件路径。将来从服务器下载的流程只负责把 `.vpk` 拿到本地，读取器不感知来源。

### 7.3 保存即生效

- 磁盘上的 `.vpk` 永远是一次成功保存的结果：完整、各条目一致、版本号齐全。
- 保存后可以随时再打开编辑，再次保存修订号 +1。
- 没有草稿：编辑会话不保存就丢弃。（视觉配方将来要上传服务器、使用时下载，那套流程另行讨论；
  本稿只保证"本地保存出来的包可直接交给那套流程上传"。）

### 7.4 按名字存取（沿用现有约定）

保留"配置一次目录、之后按名字存取"的用法：`VisionPackage.Directory` 由消费项目启动时调用
`AddVisionPackageServices(directory)` 设置一次，之后用 `VisionPackage.PathOf(name)`（= 目录 + 名字 + `.vpk`）拼路径，
所有打开 / 保存方法只收路径，避免"名字"和"路径"两种字符串重载混淆。`VisionPackage.GetAvailableNames()` 列出目录下全部包名。

> 实现说明：`VisionPackage.Open(path, layout)` 必须传布局（首版不做按布局 id 自动查找的注册表）。
> 自定义条目类型用 `VisionPackage.RegisterKind(kind)` 注册（静态注册，不经 DI），须在声明用到它的布局之前。

## 8. 扩展：自定义条目类型

项目需要框架没有的内容时（比如一个项目自己的标定结果），实现一个条目类型并注册：

```csharp
public interface IPackageEntryKind
{
    string Kind { get; }                                   // "Calibration"
    bool IsDerived { get; }
    IReadOnlyList<DependencyRole> Roles { get; }           // 需要的依赖角色及允许的 kind
    string? EditorViewName { get; }                        // 右侧编辑页（Prism 视图名），null = 只读信息页
    string StoragePath(LayoutEntry definition, string? sourceFileName);   // 在包里的相对路径
    IEnumerable<string> Validate(EntryContext ctx);        // 内容层面的校验，返回中文错误
    string? OptionsFingerprint(EntryContext ctx);          // 派生类型的生成参数指纹，没有返回 null
    void Generate(EntryContext ctx);                       // 仅派生类型实现，写到 ctx.OutputPath
}
```

注册：`VisionPackage.RegisterKind(new CalibrationKind())`。编辑器按 `EditorViewName` 把对应视图导航到右侧区域。
指纹统一由框架按存储文件哈希计算，自定义类型不用自己实现；派生类型如有生成参数，实现 `OptionsFingerprint` 返回参数指纹。

## 9. 编辑器界面

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 产品A.vpk  布局 Sample.GridPoints v1  修订 3（工程师A 10-10 10:20 保存）  ● 有未保存的修改 │
│                                          [导入原图] [全部重新生成] [保存] [关闭] │
├──────────────────────┬───────────────────────────────────────────────────────┤
│ ▸ 原图          ●     │                                                       │
│ ▾ 匹配点              │      右侧：按选中节点的 kind 切换编辑页                 │
│    匹配点 ROI   ●     │      - Image：预览、尺寸/来源/存储方式                 │
│    匹配点行列号 ●     │      - Roi：在依赖的图上画 ROI（现有绘制控件）         │
│ ▾ 校验点              │      - ShapeModel：参数、生成、试找并叠加轮廓           │
│    校验点 ROI   ◐     │      - Data<T>：PropertyGrid（显示自校验错误）          │
│    校验点行列号 ○     │      - File：导入/导出                                 │
│ ▾ 附件                │                                                       │
│    参考 Mapping ○     │                                                       │
├──────────────────────┴───────────────────────────────────────────────────────┤
│ 校验：校验点 ROI 需确认（原图已更换）；校验点行列号未填   → 当前不能保存          │
└──────────────────────────────────────────────────────────────────────────────┘
  ● 正常   ◐ 需重新生成/需确认   ○ 未建立   ✕ 无效
```

- 树由布局生成（分组 + 条目），节点状态来自会话（§5.2），会话 `EntryChanged` 时实时刷新。
- 标题栏显示布局及版本、修订号、最后保存人和时间、是否有未保存的修改。
- 校验未通过时"保存"按钮置灰，底部校验栏说明原因；点一条原因跳到对应节点。
- 关闭时有未保存的修改，提示放弃。
- 右侧页通过 Prism Region 按 kind 导航，项目自定义的 kind 也能挂进来（§8）。
- 作为框架对话框提供（替代现有 `ShapeTemplateEditorDialog`），调用方传入布局 + 包名（新建时可预填原图路径），
  关闭时带回包名、修订号、是否保存过。当前登录用户由对话框从框架身份服务取得。

## 11. 已定事项

| 事项 | 结论 |
|---|---|
| 扩展名 | `.vpk` |
| 图像 | 原图，默认无损 PNG；可选原文件原样（`Original`）或其它格式；不裁剪 |
| 草稿 | 不做。编辑会话不保存就丢弃；保存即生效，保存前强制校验 |
| 版本 | manifest 记录格式版本、布局版本、修订号；生产读取器要求布局 id 与版本**完全相等** |
| 保存人 | 保存时传入当前登录用户，记入 `savedBy` |
| `Data<T>` | 泛型、宽松反序列化、可选自校验；改字段含义须升布局版本 |
| 服务器上传 / 下载 | 后续单独讨论，本稿只管本地 |
