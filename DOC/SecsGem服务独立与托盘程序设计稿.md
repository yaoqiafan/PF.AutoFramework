## 1. 背景：现在的问题

### 1.1 每个项目各拷一份服务源码，版本已经分叉

2026-11-19 比对 `PF.SecsGem.Service/Worker.cs`：

| 位置 | 行数 |
|---|---|
| 框架 `Standard Library\PF.AutoFramework` | 789 |
| `AutoOCR\KLT_DualWorkstation` | 703 |
| `AutoOCR\KLT_SingalWorkstation` | 740 |
| `MappingShift\MotionControl` | 746 |

4 份内容各不相同。各项目安装包通过 `installer.conf` 的 `SERVICE1_CSPROJ=..\PF.SecsGem.Service\...` 编译**自己那份副本**，后果是：

- 框架里的服务端修复（S9F1 字节序、Deselect/Separate、主程序断开时复位 Host 状态、HSMS 长度头校验等）到不了现场。MappingShift 的副本曾长期停在 7 月版。
- 服务全机唯一（服务名固定 `SecsGemService`），一机多项目时**最后安装的项目说了算**，现场实际运行的服务版本不可控。
- 服务各副本里没有任何项目定制，项目差异只有 `appsettings.json` 的 `ProjectName`（由安装脚本注入）。各留一份没有必要。

### 1.2 服务状态对现场不可见

服务没有界面。现场想确认"服务在不在、主程序接没接入、Host 连没连上"，只能翻日志或打开服务管理器，排查成本高（参考 2026-11-19 现场反馈的"Host 发 S1F1 不回复"问题）。

## 2. 目标与非目标

**目标**
1. SecsGem 独立成一个项目，**单一源码、单独版本、单独安装包**。
2. 增加托盘程序：不弹主窗口，只在系统托盘显示图标，右键菜单只提供查看类功能和管理界面入口。
3. 管理界面和一切操作类功能需要超级用户校验，**不查数据库**，规则与框架一致。
4. 各项目的主程序安装包不再携带服务；服务由托盘的管理界面安装和升级。
5. 服务的 HSMS 链路配置由服务自己管理，主程序从服务导入（§9）。

**非目标**
- 不改变服务"开机自启、与是否登录无关"的运行方式。
- 不改 HSMS / SECS 报文处理逻辑。
- 业务配置（命令、VID、CEID、报表）仍由主程序管理，托盘不碰。

## 3. 总体结构

```
PF.SecsGem（独立项目，单独解决方案与安装包）
├─ PF.SecsGem.Service      Windows 服务：开机自启、无界面
├─ PF.SecsGem.Tray         托盘程序：用户登录后自启（计划任务），以管理员身份运行
│      ↕ 管理通道（命名管道，与 6800 本机通道分开）
└─ PF.SecsGem.Contracts    零依赖：服务常量、管理通道契约
```

依赖方向：`PF.SecsGem.*` 通过 NuGet（或本地开发模式的框架源码）引用框架的 `PF.Core`、`PF.Infrastructure`、`PF.SecsGem.DataBase`、`PF.Services`、`PF.UI.Resources`。

**本机通道（6800）协议常量放哪**：框架的 `InternalClient` 在 `PF.Infrastructure` 里，若引用本仓库的 Contracts 包会形成框架反向依赖本仓库。倾向放 `PF.Core`，两边都引用（待定）。

### 3.1 为什么必须是两个进程

从 Windows Vista 起，服务运行在 **Session 0**，与用户桌面隔离。服务进程创建的窗口和托盘图标，用户都看不到。所以托盘只能是单独的用户态程序。

也不考虑"取消服务、只保留托盘程序"：那样必须有人登录才会运行，有人退出托盘 SECS 就跟着断。

## 4. 通道设计

### 4.1 本机通道（6800，主程序 ↔ 服务）

保持现有报文转发，主程序接入时服务依次推送：

1. **协议版本帧**（新增命令字节）：主程序（`InternalClient`）比对版本，不兼容时报警，文案写明双方版本与应升级哪一边。旧服务不发此帧，主程序在超时（如 2s）内没收到，按"旧版本服务"告警，不阻断。
2. **链路配置帧**（新增，见 §9）：服务把当前 HSMS 链路配置推给主程序，主程序写入自己的 `SystemConfigs`。
3. 现有的 Host 连接状态帧（0x02）。

**为什么必须做**：服务独立后，它和主程序分属两个发布节奏，新旧混搭在现场必然出现；没有握手时表现为"Host 连上了但不回报文"这类难查的问题。

**实施（2026-11-20，框架 PF.Core / PF.Infrastructure 2.1.0 + 服务 2.1.0）**：
- 帧定义只在 `PF.Core.Constants.SecsGemLocalChannel`：握手帧 `0x03`、链路配置帧 `0x04`，格式 **[命令][JSON][0x0A]**——与上文草案的"[命令][4 字节长度][JSON]"不同，原因：旧版两端遇到不认识的命令字节都是丢一个字节重新同步，4 字节大端长度的首字节几乎总是 `0x00`，旧端会把它认成报文帧、按错误长度一直等，吞掉后续所有报文。JSON 用默认转义只含可打印 ASCII，旧端逐字节丢弃即可越过整帧（已用 git HEAD 的旧缓冲逻辑按 1 / 3 / 7 / 4096 字节分段验证）。
- **双向握手**：主程序也发握手帧（协议版本、程序版本、项目名），托盘概览 / 诊断页可见；旧版服务逐字节丢弃，无害。
- 主程序 2 秒（`HelloTimeout`）没收到服务握手判为旧版服务：Warn、不阻断、沿用本地 SystemConfigs。不兼容时记 Error 并指明升级哪一边。版本规则：加帧类型 / 加 JSON 字段不升 `ProtocolVersion`。

### 4.2 管理通道（命名管道，托盘 ↔ 服务）

- 管道 `\\.\pipe\PF.SecsGem.Manage`，一次连接一问一答（一行 JSON 请求 / 一行 JSON 应答），管理协议版本号不一致时服务回错误。
- ACL：本机交互用户读写、SYSTEM / 管理员 / 服务进程自身完全控制、拒绝网络访问。（已实现）
- **托盘绝不能连 6800**：服务把 6800 上新接入的连接一律当作主程序，会覆盖 `LocationClientId`。
- **写命令必须在服务端再校验一次**：超级用户校验只在托盘里做，而管道允许所有本机交互用户访问，自己写个程序直连管道就能绕过。写命令在服务端用 `RunAsClient` 取调用方身份，要求是**已提权的管理员**（托盘以管理员身份运行，天然满足）。只读命令不受限。

命令清单：

| 命令 | 读/写 | 期 | 状态 |
|---|---|---|---|
| `GetStatus` 状态快照 | 读 | 一 | 已实现（含主程序握手信息、本机通道协议版本） |
| `GetEvents(sinceSeq)` 连接事件 | 读 | 一 | 已实现 |
| `GetDiagnostics` 诊断检查 | 读 | 一 | 改为托盘侧汇总（`Diagnostics`），不需要服务命令 |
| `GetLinkConfig` 链路配置 | 读 | 一 | 已实现 |
| `ReadProjectLinkConfig(project)` 读某项目库的 SystemConfigs（不生效，供"从项目导入"填表） | 读 | 一 | 已实现（2026-11-20） |
| `GetMessages(sinceSeq)` 报文 | 读 | 二 | |
| `SetLinkConfig` 修改链路配置并重开 HSMS 监听 | 写 | 一 | 已实现（2026-11-20），服务端校验调用方为已提权管理员 |
| `DisconnectHost` 断开当前 Host | 写 | 二 | |

服务的启动 / 停止 / 安装 / 升级不走管道：托盘以管理员身份直接操作 SCM 和文件系统（§8.3）。

## 5. 托盘程序

### 5.1 运行方式

- **以管理员身份运行**（`app.manifest` 的 `requireAdministrator`）。
- **开机自启用计划任务**（用户登录时触发、"以最高权限运行"），不用注册表 Run 项：需要提升权限的程序放在 Run 项里，登录时会被 Windows 静默跳过，不弹 UAC、不报错。
- 每个登录会话只允许一个实例。
- 托盘图标按状态区分：服务未安装 / 未运行 / 旧版服务（无管理通道）/ 查询超时 / 等待主程序 / 等待 Host / Host 已连接；控制台调试实例在状态后标注【调试实例】。（已实现，图标暂用系统图标占位）

### 5.2 右键菜单（2026-11-19 定：只留查看类）

| 菜单项 | 需要超级用户 |
|---|---|
| 状态摘要 / 项目 · Host · 收发计数（只读） | 否 |
| 打开服务日志目录 / 打开协议日志目录 | 否 |
| 管理界面… | **是** |

## 6. 超级用户校验（已实现）

- 规则唯一来源：框架 `PF.Core.Constants.SuperUserCredential`（用户名 `SuperUser` 不区分大小写，密码为本机当前时间 `yyyyMMddHH00`）。框架 `UserService`、调试时的自动登录、托盘三处共用同一份代码。
- 不查数据库：托盘不连任何项目的配置库。
- 会话：滑动过期 10 分钟（登录或每次受控操作后重新计时），管理界面内可手动注销。
- 操作日志：`D:\PF_Logs\SecsGem\Tray\Tray_yyyy-MM-dd.log`，记录验证成功 / 失败、每项操作及结果，附 Windows 登录用户名。
- 已知风险（与主程序相同，已记入审计遗留清单）：规则可以推算，强度有限。

## 7. 安装、升级与项目绑定

### 7.1 安装包（托盘安装包）
- 内容：托盘程序 + **同版本的服务文件**（放在托盘安装目录的 `ServicePackage\` 下，供管理界面安装 / 升级服务）。
- 负责：安装托盘、创建计划任务自启、检查 .NET 8 运行时、首次安装时注册并启动服务（与管理界面「安装服务」走同一套逻辑）。
- 服务注册沿用已验证的做法：`net stop` 同步等待 → `sc delete` → 重试 `sc create` 最多 15s，失败时提示；卸载时只删除 ImagePath 指向本安装目录的服务。
- 2026-11-19 做过一个临时验证版（Inno Setup，单服务、`ProjectName` 写死），可作为起点。

### 7.2 ProjectName（过渡期）
- §9 实施前：服务仍从 `appsettings.json` 的 `ProjectName` 读项目的 `SecsGemConfig.db`，读不到时拒绝启动；安装 / 升级服务时**必须保留原有的 `ProjectName`**。
- §9 实施后：服务不再需要 `ProjectName`，仅首次迁移时用它从项目库导入一次链路配置；主程序启动时的项目归属校验（`VerifySecsServiceProjectBinding`）随之改为"链路配置一致性"提示或取消。

### 7.3 项目侧的迁移
1. 删除各项目里的 `PF.SecsGem.Service` 副本（KLT_DualWorkstation、KLT_SingalWorkstation、MappingShift/MotionControl 三处）。
2. 各项目 `installer.conf` 设 `SERVICE_COUNT=0`，主程序安装包不再带服务。
3. 现场部署：先装托盘安装包（含服务），再装主程序包；之后服务升级在托盘管理界面完成。
4. 框架仓库原 `PF.SecsGem.Service` 移入新项目，`AGENTS.md` 的架构图和相关说明同步更新。

## 8. 管理界面规划（2026-11-19 定）

### 8.1 定位
主程序 SECS 调试页（`PF.Modules.SecsGem`）已有命令编辑、配置导入导出、报文收发、通讯日志，管理界面**不重复**这些。它的价值：
1. 主程序没开、崩溃或卡住时也能看——现场"Host 说设备不回报文"，第一步要分清是服务、主程序还是网络的问题。
2. 看得到主程序看不到的服务层信息：HSMS 控制报文（Select / Linktest / Deselect / Separate / Reject）、链路建立与断开过程、6800 本机通道接入断开、服务自身错误。

原则：**托盘管服务与链路，业务配置归主程序。**

### 8.2 布局与页面

窗口：`pf:Window` + `WindowWin10`（框架统一风格），**左侧导航栏**（与主程序侧边栏风格一致），右侧内容区。只在窗口打开时向服务拉取数据，关闭即停止。

| 页面 | 内容 | 期 |
|---|---|---|
| **概览** | 四块状态卡片：服务（版本、运行时长、启动时间）、主程序通道（是否接入、接入时间）、HSMS（监听地址、Host 对端地址、连接时长）、计数（收 / 发 / 控制报文）；最近 5 条服务警告或错误 | 一 |
| **操作** | 见 §8.3 | 一 |
| **连接事件** | 时间线：主程序接入 / 断开、HSMS 开启 / 关闭、Host 接入 / 断开、Select / Deselect / Separate / Reject、非法长度头重同步。服务内存环形缓冲 500 条，托盘按序号增量拉取 | 一 |
| **诊断** | 一键检查并给出处理建议（红黄绿）：6800 与 HSMS 端口被谁占用、服务注册路径与安装版本、链路配置是否存在且有效、协议版本、日志盘剩余空间 | 一 |
| **链路配置** | 显示并（§9 实施后）修改 HSMS IP、端口、DeviceID、超时；修改后经 `SetLinkConfig` 生效（会断开当前 Host，需确认） | 一显示 / 二修改 |
| **实时报文** | 时间、方向、SxFy、W 位、SystemBytes、长度；按 SxFy / 方向过滤、暂停滚动、点开看解析结构、导出。服务内存环形缓冲 2000 条，不额外写盘（协议日志已有完整记录） | 二 |

### 8.3 操作页

所有操作都已在进入管理界面时通过超级用户校验；每项操作写托盘操作日志。

| 操作 | 说明 |
|---|---|
| 启动 / 停止 / 重启服务 | 按 SCM 当前状态启用。停止、重启二次确认（会中断 SECS 通讯），Host 已连接时额外提示 |
| **安装 / 升级服务（随托盘附带）** | 比较已安装服务版本与托盘附带的 `ServicePackage\` 版本，显示"已安装 vX / 可安装 vY"，一键安装或升级 |
| **从文件安装服务** | 选一个服务包 zip（含版本清单），离线现场或需要回退到指定版本时使用 |
| 断开当前 Host | 二期，经 `DisconnectHost` |
| 导出诊断包 | 二期：服务日志、协议日志、链路配置、诊断结果打成一个 zip |
| 注销超级用户 | 立即结束会话并关闭管理界面 |
| 退出托盘 | 二次确认；退出后需重新登录 Windows 或手动启动托盘才会再出现，不影响服务 |

**安装 / 升级服务流程**：
1. 校验服务包：版本清单、文件完整性。
2. 二次确认；Host 已连接时提示"会中断 SECS 通讯，建议停机时操作"。
3. 停止服务，备份当前服务目录。
4. 复制新文件；**保留现有 `appsettings.json` 中的 `ProjectName`**（§9 实施前）以及服务自己的链路配置文件。
5. 服务未注册时按 §7.1 的参数注册；已注册则沿用原安装位置。
6. 启动服务，经管理通道确认版本已变为新版本。
7. 任一步失败：自动恢复备份并启动旧版本，报告失败原因。
8. 全过程写托盘操作日志。

服务包格式：服务发布目录 + 版本清单文件（服务版本、管理协议版本、本机通道协议版本），构建脚本产出 `PF.SecsGem.Service_{版本}.zip`，同时解压到托盘安装包的 `ServicePackage\`。

## 9. 链路配置独立（2026-11-19 定）

### 9.1 依据
服务读项目的 `SecsGemConfig.db` **只读 `SystemConfigs` 一张表**（`Worker.ReloadSystemParamAsync`：HSMS IP、端口、DeviceID 等链路参数），命令 / VID / CEID 等表服务都不用。把这部分收归服务自己保存后：

- 服务与项目脱钩：`ProjectName` 不再需要，一机多项目的服务归属、主程序启动时的归属告警问题随之消失——与"一台机器只有一个服务"的现实一致。
- 托盘可以在主程序打不开时修改链路参数。

### 9.2 范围：`SystemConfigs` 全部字段（2026-11-19 定）

链路配置 = 原 `SystemConfigs` 表的**全部字段**，即 `PF.Core.Entities.SecsGem.Params.SecsGemSystemParam`（与实体 `SecsGemSystemEntity` 一一对应）：

| 分组 | 字段 |
|---|---|
| 连接 | `IPAddress`、`Port`、`DeviceID` |
| 超时（毫秒） | `T3`、`T4`、`T5`、`T6`、`T7`、`T8`、`BeatInterval` |
| 设备标识 | `MDLN`、`SOFTREV`（S1F2 / S1F14 应答用） |
| 服务 | `ServiceName`、`AutoStart`、`StartupDelayMs` |

`ServiceName` 实际固定为 `SecsGemService`（§1），保留字段只为与现有结构兼容。

### 9.3 方案
- **存储**：服务自己的链路配置文件 `D:\PFConfig\PFAutoFrameWork\SecsGemService\link.json`（`SecsGemSystemParam` 的 JSON，原子写入）。放在配置根目录下而不是服务安装目录，升级 / 重装服务不会被覆盖，也和现场备份习惯一致；目录里没有 `SystemParamsCollection.db`，不会被 `Migrate-Config.ps1` 误认为项目目录。
- **唯一来源是服务**：托盘经 `SetLinkConfig` 修改（服务端校验调用方为已提权管理员，§4.2）；保存后服务关闭并按新参数重开 HSMS 监听（会断开当前 Host，托盘先确认）。
- **向主程序传递参数**：
  - 主程序每次接入 6800 时，服务推送**链路配置帧**：`[命令字节][长度 4 字节，大端][SecsGemSystemParam 的 UTF-8 JSON]`，命令字节与版本帧一起定义在 PF.Core（§3）。
  - 托盘修改配置后，服务向已接入的主程序**再推一次**，主程序无需重连即可拿到新值。
  - 主程序收到后写入自己的 `SystemConfigs`。现有代码路径（`InternalClient` 用 DeviceID 拼报文头、各模组读 MDLN / SOFTREV、调试页显示）**不用改**，读的仍是本地表，只是表的内容由服务下发。
- **主程序 SECS 调试页**：系统参数这 15 项改为只读，标注"由 SECS 服务管理，请在托盘管理界面修改"；原"导入 / 保存系统参数"对这部分停用，避免现场用旧方式改了、下次接入又被服务覆盖。
- **首次迁移**：服务启动时若没有 `link.json`，按 `appsettings.json` 的 `ProjectName` 从该项目 `SecsGemConfig.db` 的 `SystemConfigs` 导入一次并写出 `link.json`；导入不到时用 `SecsGemSystemParam` 默认值并在托盘诊断页标红。之后不再读项目库。
- **旧服务兼容**：旧版服务不推送配置帧，主程序在超时内没收到就沿用本地 `SystemConfigs`（即现有行为），并按"旧版服务"提示（§4.1）。

**实施时的调整（2026-11-20）**：
- 帧格式见 §4.1"实施"（文本帧，不带长度头）。
- **没有链路配置时不开 HSMS 监听**，不用 `SecsGemSystemParam` 默认值建链（草案写的"导入不到时用默认值"会让服务以 127.0.0.1:5000 等默认值静默运行）；事件与托盘诊断标红，提示到「链路配置」页填写。
- link.json **损坏时不自动迁移覆盖**：坏文件先备份，项目库里的可能是旧值，等人在托盘处理。
- 迁移只读打开项目库，**库不存在不创建**（旧服务启动时 `EnsureCreated`，项目名配错就在配置根目录下凭空建出项目目录与空库）；服务启动不再创建 / 打开任何项目库。
- 服务包 `appsettings.json` 的 `ProjectName` 默认改为空串（此前是 `PF.Application.Shell`，新机器若恰好有 Demo 的库会被误迁移）；托盘首次安装时"迁移来源"可选可不选。
- 托盘「链路配置」页"从项目导入"：经 `ReadProjectLinkConfig` 读出填表，保存才生效——一机多项目切换时手动导入即可（按项目分档的方案用户定为先不做）。
- 主程序本地系统参数为空时也连接服务（此前 `InitializationClient` 直接返回 false，新机器上配置永远到不了主程序）。
- 调试页只读的判定是"握手成功且服务声明 `ManagesLinkConfig`"：接的是旧版服务时仍可在主程序维护。

### 9.4 框架侧改动范围
- `PF.Core`：本机通道帧定义（版本帧、链路配置帧）。
- `InternalClient`（`PF.Infrastructure`）：处理两种新帧；收到配置帧后写本地 `SystemConfigs` 并更新报文头用的 DeviceID。
- `SecsParameterViewModel`（`PF.Modules.SecsGem`）：系统参数只读化，导入 / 保存停用这部分。
- `VerifySecsServiceProjectBinding`（`PF.Application.Base`）：服务不再依赖 `ProjectName` 后取消，或改为"本地 SystemConfigs 与服务下发是否一致"的提示。

## 12. 二期实施计划（2026-11-20 拟定，待确认）

范围沿用 §8 已定的三项（实时报文、断开当前 Host、导出诊断包），外加一项建议（接入方识别）和开工前的一期验收。

### 12.0 开工前：一期现场验收

一期的托盘安装包、管理界面五页、服务安装 / 升级 / 失败回退、开机自启计划任务、链路配置修改都还没在现场机器上完整走过。二期开工前先在一台机器上跑完一期验收，问题先修，避免二期叠在没验证过的基础上。

### 12.1 兼容规则（二期所有改动都要遵守）

- **新增管理命令不升 `ManagementChannel.ProtocolVersion`**：服务按版本**严格相等**校验（`ManagementPipeServer.DispatchAsync`），一旦升级，新托盘连旧服务、旧托盘连新服务都会被整体拒绝。新命令由旧服务回"不支持的命令"，托盘据此把对应功能置灰并提示"服务版本过低，请在「操作」页升级"。
- 本机通道（6800）协议二期不改，框架包不需要随二期升级。
- 版本：托盘 / 服务 / Contracts 统一升 **2.2.0**。

### 12.2 实时报文（P2-1）

**服务端**
- `ServiceRuntimeState` 新增报文环形缓冲（`MessageCapacity = 2000`，与事件缓冲同样按递增序号增量拉取）。每条：序号、时间、方向（来自 Host / 发往 Host）、DeviceID、Stream、Function、W 位、SystemBytes、SType（区分数据 / 控制报文）、总长度、原始字节（单条超过 64 KB 时截断并标记）。
- 采集点与协议日志相同：`Worker` 里写 `SecsGemWriteLog` 的三处（收 Host、转发主程序报文、控制报文应答）各加一行入缓冲，只解析 14 字节头部，开销可忽略；不额外写盘（协议日志已有完整记录）。
- 新增只读命令（不要求管理员）：
  - `GetMessages(sinceSeq, max)`：摘要列表，不含正文。
  - `GetMessageDetail(seq)`：十六进制 + 解析后的 SML 文本（用服务已有的 `SecsGemMessageProcessor`，与协议日志的解析结果一致）；已被环形缓冲挤掉时返回"已过期"。

**托盘**
- 新页面「实时报文」：列表列为时间 / 方向 / SxFy / W / SystemBytes / 长度 / 类型；窗口打开且页面可见时每秒增量拉取，托盘本地最多保留 2000 条。
- 过滤：方向、SxFy 关键字、隐藏 Linktest；暂停滚动；选中一行拉取详情显示在下方。
- 导出当前列表（含详情 SML）为文本文件。

### 12.3 断开当前 Host（P2-2）

- 服务：新增 `DisconnectHost` 命令，调用方须为已提权管理员（与 `SetLinkConfig` 同一校验）。断开的是当前这条 TCP 连接，**HSMS 监听保持开启**，Host 可以立即重连。Host 未连接时返回提示，不报错。记 Warning 事件（含操作者）。
- 托盘：「操作」页按钮，Host 未连接时置灰；二次确认，说明"只断开当前连接，Host 会自动重连；要阻止 Host 连接请停止服务"。

### 12.4 导出诊断包（P2-3）

- 由托盘直接打包（托盘以管理员运行，能读所有文件），**不新增服务命令**；服务无响应时照样能导出文件部分。
- zip 内容：
  - 经管理通道取的快照：`status.json`、`events.json`（全部事件）、`messages.json`（最近 2000 条报文摘要，P2-1 完成后）；取不到时写明"服务未响应"。
  - `link.json` 副本、服务目录的 `appsettings.json` 与 `package.json`。
  - 诊断页全部检查结果（`diagnostics.txt`）。
  - 服务注册信息：ImagePath、启动类型、运行账户、文件版本。
  - 日志：服务运行日志与 `Protocol\` 协议日志（默认最近 3 天，可选 1 / 3 / 7 天）、`startup-error.log`、托盘操作日志。
- 文件名 `PF.SecsGem_诊断包_{机器名}_{yyyyMMdd_HHmmss}.zip`，默认存到桌面；打包前估算大小，超过 200 MB 时提示缩小天数。

### 12.5 6800 接入方识别（P2-4，建议，待确认）

现场最难查的问题是"主程序明明连着，却收不到报文"——本机另一个程序也连了 6800，把主程序顶替了（§10 限制）。
- 服务记录每个 6800 连接的远端端口；托盘用已有的 `PortOwner`（按端口查进程）解析出进程名与 PID，显示在概览「主程序通道」卡片上。
- 发生"新连接顶替旧连接"时，服务记 Warning 事件，托盘概览醒目提示，写明前后两个进程。
- **不改变顶替行为**：主程序崩溃重启后要能直接重新接入，改成拒绝新连接会带来新问题。
