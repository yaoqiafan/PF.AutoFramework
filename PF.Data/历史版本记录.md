# PF.Data 历史版本记录

> 2.0.0 之前的版本说明，2026-11-19 框架升级 2.0.0 时自 `PF.Data.csproj` 的 PackageReleaseNotes 原样移出。
> 2.0.0 起的变更见 csproj 的 PackageReleaseNotes。

## v1.0.4 (2026-10-23) — 报警定义新增清除等级字段

[数据库 Schema 变更 — 自动补列，无需手动迁移]
- AlarmDefinitionEntity 新增 RequiredLevel（UserLevel，默认 Operator）：手动清除该报警及其活跃时复位所需的最低用户等级。
- AlarmHistory.db 的 AlarmDefinitions 表对应新增 RequiredLevel INTEGER NOT NULL DEFAULT 0 列，
  由 PF.Services 1.0.9 的 AlarmDictionaryService 启动时检测并自动补列；老库升级后全部为操作员，行为不变。

## v1.0.3 (2026-07-07) — 仓储查询性能优化 + 通讯实例默认配置契约

[破坏性变更 — 补充说明，随通讯管理框架一并引入]
- IDefaultParam 新增接口成员 GetCommunicationDefaults()，返回
  Dictionary<string, CommunicationParam>，用于声明通讯实例（TcpServer/TCPClient/
  FileTransferChannel 等）的默认配置，与既有 GetHardwareDefaults() 并列。
  所有实现 IDefaultParam 的项目侧 DefaultParameters 类均需补充此方法（无 TCP 通讯
  依赖的硬件可返回空字典）。
- 新增实体 CommunicationParam（PF.Data.Entity.Category），结构对齐 HardwareParam。

[修复]
- PurgeOldDataAsync 改用 ExecuteDeleteAsync（避免先查询后删除的两次往返）；
  GenericRepository 只读查询统一加 AsNoTracking，降低 EF Core 变更追踪开销。

## v1.0.2 (2026-06-17) — 报警实体扩展（SECS/GEM 字段）+ 数据库 Schema 变更

[数据库 Schema 变更 — 需执行迁移]
- AlarmDefinitions 表（AlarmHistory.db）新增三列：
    MessageEn     NVARCHAR(35)   — 英文报警描述，SECS/GEM S5F1 上传用
    MessageID     INTEGER        — 整型报警 ID（默认 0）
    MessageIDHex  NVARCHAR(40)   — 英文报警文本
  若直接覆盖 dll 而不迁移，旧库可正常读写（EF Core 对未知列无感），
  但新字段将读取为默认值（空字符串 / 0）。

[实体变更]
- AlarmDefinitionEntity 新增属性：
    MessageEn    ([MaxLength(35)])
    MessageID    (int)
    MessageIDHex ([MaxLength(40)])
- AlarmDbContext Fluent API 为 MessageEn（MaxLength 35）和
  MessageIDHex（MaxLength 40）补充列长度约束，与数据库类型匹配。
- AlarmRecordEntity 清理空白行（无逻辑变化）。
